# VK → SoundCloud

Инструмент переносит список треков из VK Музыки в новый плейлист на SoundCloud. Аудиофайлы он не скачивает и не загружает. Для каждой строки «Исполнитель — Название» он находит трек в SoundCloud и добавляет его в плейлист в том же порядке, что и в VK.

Работает в два шага:

1. **VK → `tracks.txt`.** Скрипт `vk_export.js` запускается в консоли браузера на странице «Моя музыка». Он только читает страницу: логин, пароль и токены VK не нужны.
2. **`tracks.txt` → SoundCloud.** Программа `python -m vk2sc` ищет каждый трек, сама пробует очищенные варианты запроса, сама выбирает лучшее совпадение, сомнительные треки пропускает (они попадают в отчёт) и в конце создаёт приватный плейлист «Из VK». Ручного выбора кандидатов нет: единственный вопрос — подтверждение перед созданием плейлиста, а с `--yes` нет и его.

Прогресс сохраняется в `state.json` после каждого трека. После Ctrl+C, падения или ограничения запросов со стороны SoundCloud повторный запуск продолжит с того же места: заново ничего не ищется, дублей в плейлисте не появится.

## Что нужно знать заранее

- Программа работает с **внутренним API SoundCloud** (`api-v2.soundcloud.com`), тем же, что использует сам сайт. Для ключей к официальному API, по словам утилиты регистрации SoundCloud, может понадобиться подписка Artist Pro, а сервисы переноса библиотек там запрещены без одобрения SoundCloud. Внутренний API формально нарушает правила SoundCloud и может сломаться без предупреждения. Программа делает паузу 1,5–2 с между запросами и останавливается, если SoundCloud начинает отказывать.
- Для создания плейлиста нужен **ваш токен SoundCloud** из cookie браузера. Он даёт полный доступ к аккаунту. Храните его только в `.env`, никому не пересылайте, а после переноса выйдите из SoundCloud в браузере: при выходе токен перестаёт действовать.
- В VK ничего не меняется. В SoundCloud программа только создаёт свои плейлисты и меняет список треков в них. Лайки, подписки и ваши существующие плейлисты она не трогает.

## Установка

Нужен Python 3.9 или новее.

```bash
git clone <адрес репозитория> vk2sc && cd vk2sc
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # Windows: copy .env.example .env
```

## Шаг 1. Выгрузить список из VK

1. Откройте vk.com в Chrome, Яндекс Браузере, Edge или Firefox. В левом меню выберите «Музыка», затем вкладку со своими треками. Адрес будет вида `vk.com/audios123456` или, в новой VK Музыке, `vk.com/music/…`: скрипт понимает обе вёрстки. Можно открыть и любой плейлист, скрипт выгрузит его содержимое.
2. Откройте консоль разработчика: **F12** (на Mac **Cmd+Option+J**), вкладка **Console / Консоль**.
3. Откройте файл `vk_export.js` из этой папки в любом текстовом редакторе, выделите всё (Ctrl+A), скопируйте, вставьте в консоль и нажмите Enter.
   - Chrome и Яндекс Браузер при первой вставке могут попросить набрать `allow pasting`. Наберите, нажмите Enter и вставьте скрипт ещё раз. В Firefox нужно набрать `разрешить вставку`.
4. Скрипт сам прокрутит список до конца и соберёт треки. Не переключайте вкладку, пока он работает: для нескольких сотен треков это минута-две. Ход работы виден в консоли: «Собрано треков: 120…».
5. В конце браузер скачает файл **`tracks.txt`**. Положите его в папку с программой.

Что лежит в файле:

```
# Экспорт из VK 2026-09-26, треков: 312, способ: VK Музыка (data-testid)
Imagine Dragons — Believer | 3:24
Miyagi, Andy Panda — Kosandra | 3:36
Party Animals — Have You Ever Been Mellow (Flamman & Abraxas Radio Mix) | 3:05
```

Если что-то пошло не так:

- **«Не нашёл ни одной аудиозаписи»**. Проверьте, что открыта именно страница со списком треков и список виден на экране. Если VK поменял вёрстку, запустите диагностику (см. ниже) и пришлите её вывод, и я обновлю селекторы. Файл в этом случае не создаётся, пустого `tracks.txt` не будет.
- **«Похоже, названия треков считываются неправильно»**. У заметной части треков (больше 20%) название вышло пустым, из одних цифр или похожим на битрейт («320», «~128»). Файл в этом случае тоже не создаётся. Обычно так бывает из-за расширения браузера, которое добавляет в строки треков бейджи: битрейт, размер файла, кнопку скачивания. Такие бейджи скрипт пропускает, но если расширение переделало строку сильнее, отключите его, обновите страницу и запустите скрипт снова.
- **«Пропущено треков без названия»**. У нескольких строк название не нашлось. Их нет в файле, список с исполнителями и длительностями есть в консоли. Допишите их в `tracks.txt` вручную.
- **«Взял только основной блок…»**. На странице было несколько блоков с музыкой (например, «Недавно прослушанные»), и скрипт взял самый большой. Если нужны все блоки, выполните в консоли `window.VK2SC_OPTIONS = {onlyBiggestSection: false}` и запустите скрипт ещё раз.
- **Список обрезан.** Если VK долго подгружает треки, увеличьте паузу: `window.VK2SC_OPTIONS = {stepMs: 2000}`, затем снова вставьте скрипт.
- Полный текст после выгрузки остаётся в `window.vk2scResult.text`. Если файл не скачался, выполните `copy(window.vk2scResult.text)` (в Chrome это копирует текст в буфер) и вставьте его в `tracks.txt` вручную.

Скрипт не отправляет ничего по сети и ничего не меняет в аккаунте, это видно по его коду. Вставлять в консоль стоит только тот код, который вы понимаете или которому доверяете.

**Диагностика.** Если экспорт не находит треки или берёт не те названия, вставьте в консоль на той же странице `vk_diagnose.js`. Он выведет устройство первых трёх строк списка и скопирует результат в буфер обмена. Пришлите этот вывод. Чтобы показать конкретный трек, перед запуском выполните `window.VK2SC_FIND = "часть названия или исполнителя"` и пролистайте список до этого трека. Длинные служебные хэши в выводе заменяются на «…».

### Запасной вариант: `tracks.txt` вручную

Если скрипт перестал работать, `tracks.txt` можно составить самому: одна строка — один трек.

```
Исполнитель — Название
Кино — Группа крови | 4:45
# комментарий: решётка и пробел; пустые строки тоже пропускаются
#2Маши — Босая
```

- Разделитель — длинное тире «—». Подойдут также «–» и « - » с пробелами.
- Длительность необязательна, её можно дописать в конце через ` | `. С ней сопоставление заметно точнее, особенно когда у песни есть несколько версий.
- Комментарий начинается с «# » (решётка и пробел). Строка «#2Маши — Босая» — это трек.
- Если вместо названия стоит битрейт («~128», «256 kbps»), трек получает статус «битое название». Программа его не ищет, в том числе по одному исполнителю, и не добавляет в плейлист. Голое число вроде «320» или «128» считается битрейтом, только если в том же списке есть и другие такие строки (признак сбоя экспорта). Одиночное «Artist — 320» ищется как обычная песня, но совпасть может только с треком, который называется так же. Числа, которые не бывают битрейтом, всегда остаются названиями: «Arctic Monkeys — 505», «Taylor Swift — 22».
- Технические хвосты в названиях из VK — «(VK.COM)», «[vk.com reupload]», «(Reupload)», «(uploaded by …)», «[source: vk.com]», «(vk rip)» — в `tracks.txt` можно не чистить: программа уберёт их сама, но только для поиска и сравнения. Смысловые пометки вроде «(Remix)», «(Live)», «(Slowed)», «(feat. …)» остаются.
- Кодировка UTF-8. Файлы из старого «Блокнота» в cp1251 и в UTF-16 тоже читаются.

## Шаг 2. Пробный прогон без изменений в аккаунте

```bash
python -m vk2sc --dry-run
```

Токен для этого шага не нужен, вопросов программа не задаёт. Она ищет треки, сама выбирает совпадения и пишет отчёт `report.csv`. Плейлист не создаётся. Все результаты сохраняются в `state.json`, поэтому на шаге 4 поиск не повторяется.

Для сотни треков это около 5–10 минут: обычно 1–2 поисковых запроса на трек (для плохо ищущихся — до 5) и пауза 1,5–2 с между ними.

### Что видно во время работы

```
[16/412] Bladee, Ecco2k — Gotham CityGirls Just Want to Have Fun (VK.COM) [2:14]
  поиск: Bladee, Ecco2k Gotham CityGirls Just Want to Have Fun (VK.COM)
  результат недостаточно хороший
  повторный поиск (очищенный): Bladee, Ecco2k Gotham CityGirls Just Want to Have Fun
  лучший вариант: Bladee, Ecco2k — Girls just want to have fun [2:14]
  score: 90
  title: 84 (слов совпало: 100%)
  artist: 100 (тот же набор исполнителей)
  duration: +0 сек
  version conflict: нет
  margin: +29
  → автоматически выбран: точный исполнитель + длительность
```

После «→» указана причина решения: по какому правилу кандидат принят или почему отвергнут («другая версия», «длительность отличается на 42 с», «несколько равных вариантов»…). `margin` — насколько лучший кандидат опережает следующую другую запись, которую тоже можно было бы выбрать.

Для каждого трека программа пробует запросы по очереди, пока не найдёт уверенное совпадение (не больше 5):

1. **исходный** — исполнитель и название как в `tracks.txt`;
2. **очищенный** — без «(VK.COM)», «(Official Audio)», feat.-гостей;
3. **без ё / транслит** — для кириллицы («Елка Прованс», «zemfira hochesh»);
4. **основной исполнитель** — первый из нескольких («Miyagi & Andy Panda» → «Miyagi»);
5. **название + исполнитель** и **только название** — самые широкие запросы для плохо ищущихся треков.

Результаты всех запросов сравниваются вместе, и берётся лучший кандидат, а не первый в выдаче SoundCloud. Поиска по одному исполнителю нет никогда. Если ничего достаточно похожего не нашлось, трек пропускается и отмечается в отчёте: лучше пропустить несколько треков, чем добавить чужую песню.

С `-v` для каждого трека выводится до 5 лучших кандидатов с оценками и пометками «другая версия», «другая часть», «те же исполнители».

### Ручной режим (по желанию)

С флагом `--interactive` работает прежний режим: если совпадение сомнительное, программа показывает до 5 кандидатов и спрашивает:

- **номер** — взять этого кандидата;
- **Enter** — пропустить трек;
- **любой текст** — искать заново по вашему запросу (чтобы искать число, например песню «1979», начните с косой черты: `/1979`);
- **ссылка на трек SoundCloud** — взять именно его;
- **Ctrl+C** — остановиться, прогресс сохранится.

`--interactive --review` ещё раз предлагает выбор для пропущенных и ненайденных треков по сохранённым кандидатам. Ваш ручной выбор программа потом никогда не пересчитывает.

Пометка «только Go+» означает, что без подписки Go+ в плейлисте будет играть 30-секундный отрывок. «Недоступен в регионе» — трек заблокирован для вашей страны.

## Шаг 3. Токен SoundCloud

1. Войдите на soundcloud.com в браузере.
2. Нажмите F12:
   - **Chrome, Яндекс, Edge:** вкладка **Application** (Приложение) → слева **Storage → Cookies → https://soundcloud.com**;
   - **Firefox:** вкладка **Storage** (Хранилище) → **Cookies → https://soundcloud.com**.
3. Найдите строку **`oauth_token`** и скопируйте значение из колонки Value. Оно выглядит примерно так: `2-123456-78901234-AbCdEfGhIjKl`.
4. Впишите его в `.env`:

```
SOUNDCLOUD_OAUTH_TOKEN=2-123456-78901234-AbCdEfGhIjKl
```

Токен должен стоять в той же строке сразу после «=», без пробелов и переносов. Файл должен называться ровно `.env`: Блокнот иногда сохраняет его как `.env.txt`, а Windows по умолчанию скрывает расширения (проверить настоящее имя: `Get-ChildItem -Force .env*`). Если программа всё равно пишет «нужен SOUNDCLOUD_OAUTH_TOKEN», в следующей строке она подскажет, что не так с файлом: его нет, он называется `.env.txt`, строка пустая, токен на строке ниже, строка закомментирована. Сам токен при этом не выводится.

Если позже появится ошибка «SoundCloud отклонил запрос (HTTP 401)», значит токен устарел: вы вышли из аккаунта или сменили пароль. Скопируйте его заново.

## Шаг 4. Создать плейлист

```bash
python -m vk2sc
```

1. Досчитает то, что не было найдено на шаге 2 (сама, без вопросов).
2. Покажет, что собирается сделать, и попросит подтверждения:

```
Аккаунт SoundCloud: your_name
  • создать приватный плейлист «Из VK» — 312 треков
Продолжить? [y/N]:
```

Если не ответить `y` (или «да»), в аккаунте ничего не изменится. Плейлист называется «Из VK», другое название задаётся флагом `--title "Название"`. В плейлист SoundCloud помещается не больше 500 треков, поэтому длинный список делится на «Из VK», «Из VK (2)» и так далее.

Полностью без вопросов, от поиска до плейлиста:

```bash
python -m vk2sc --yes
```

Если после этого вы допишете треки в `tracks.txt` или выберете пропущенные через `--interactive --review`, повторный запуск обновит те же плейлисты, а не создаст новые.

### Если SoundCloud не даёт создать плейлист (HTTP 403, DataDome)

Изменения в аккаунте SoundCloud закрыты защитой от ботов DataDome: запрос на создание плейлиста не из браузера получает 403 с капчей, хотя токен верный (профиль при этом читается нормально). В этом случае программа пишет:

```
SoundCloud пропускает изменения в аккаунте только из браузера (защита от ботов DataDome). Токен при этом в порядке.
Создал файл C:\...\soundcloud_playlists.js — он создаст плейлисты прямо из браузера («Из VK» — 500 треков, «Из VK (2)» — 487 треков):
```

Дальше всё делается за минуту:

1. Откройте https://soundcloud.com в браузере, где вы вошли в аккаунт.
2. Нажмите F12 и перейдите на вкладку **Console (Консоль)**.
3. Откройте `soundcloud_playlists.js` в Блокноте (`notepad soundcloud_playlists.js`), нажмите Ctrl+A и Ctrl+C, вставьте в консоль и нажмите Enter. Если браузер попросит, сначала наберите `allow pasting`.
4. Если SoundCloud попросит проверку «я не робот» (в консоли будет «ЗАКРОЙТЕ панель разработчика»), закройте панель F12 — при открытой панели проверка не решается — и пройдите её на странице. Скрипт ждёт до 15 минут и продолжает сам; ход работы виден в плашке внизу слева и в заголовке вкладки.
5. Дождитесь «vk2sc: готово ✓». Открыв F12 снова, увидите таблицу со ссылками.
6. Запустите `python -m vk2sc` ещё раз: программа найдёт эти плейлисты и отметит треки в отчёте как добавленные.

Скрипт работает от имени открытой вкладки: берёт токен из cookie сайта и сам ничего никуда не отправляет, кроме api-v2.soundcloud.com. Повторный запуск не создаёт дублей: плейлист находится по id, запомненному в браузере, или по названию и метке «vk2sc» в описании, и его список треков заменяется целиком. Ваши плейлисты с таким же названием, но без метки, скрипт не трогает. Если проверка «я не робот» не пройдена за 15 минут или появляется снова и снова, обновите страницу, подождите 10–15 минут и вставьте скрипт снова.

Сразу получить скрипт, не пробуя API и даже без токена в `.env`:

```bash
python -m vk2sc --browser
```

## Флаги

| Флаг | Что делает |
|---|---|
| `--dry-run` | Только поиск и отчёт. Плейлист не создаётся, токен не нужен, вопросов нет. |
| `--yes`, `-y` | Не спрашивать подтверждения перед созданием/изменением плейлиста. |
| `--tracks ФАЙЛ` | Другой файл со списком (по умолчанию `tracks.txt`). |
| `--title "НАЗВАНИЕ"` | Название плейлиста (по умолчанию «Из VK»). |
| `--public` | Сделать плейлист публичным (по умолчанию приватный). |
| `--browser` | Не менять плейлисты через API, а создать `soundcloud_playlists.js` для консоли браузера на soundcloud.com (см. «Если SoundCloud не даёт создать плейлист»). Токен не нужен. |
| `--interactive` | Прежний ручной режим: спрашивать выбор кандидата, если совпадение сомнительное. |
| `--review` | Вместе с `--interactive`: ещё раз предложить выбор для пропущенных и ненайденных треков. |
| `--rematch` | Пересчитать автоматические совпадения, найденные прошлой версией алгоритма (см. ниже). Ручной выбор не трогается. |
| `--no-input` | Ничего не спрашивать, даже если запуск из терминала. Плейлист тогда меняется только вместе с `--yes`. |
| `--threshold N` | Порог уверенности для автодобавления, 0–100 (по умолчанию 85). |
| `--delay СЕК` | Пауза между запросами (по умолчанию 1.5, минимум 1). То же — `REQUEST_DELAY` в `.env`. |
| `--state ФАЙЛ` | Файл прогресса (по умолчанию `state.json`). |
| `--report ФАЙЛ` | Файл отчёта (по умолчанию `report.csv`). |
| `-v` | Подробный вывод в терминал. |

## Отчёт `report.csv`

Разделитель — точка с запятой, кодировка UTF-8 с BOM, поэтому русский Excel открывает файл двойным щелчком. Колонки:

| Колонка | Что в ней |
|---|---|
| `line` | номер строки в `tracks.txt` |
| `original_artist`, `original_title` | исполнитель и название как в `tracks.txt` (не изменяются) |
| `search_title` | очищенное название, по которому шёл поиск |
| `matched_artist`, `matched_title`, `soundcloud_url` | что выбрано в SoundCloud; для «низкой уверенности» — лучший отвергнутый вариант, чтобы его было легко проверить |
| `score` | оценка похожести 0–100 |
| `status` | см. ниже |
| `search_variant` | каким запросом найден трек: исходный, очищенный, без ё, транслит, основной исполнитель, название + исполнитель, только название |
| `note` | причина решения: правило, по которому трек принят («точный исполнитель + длительность», «лучший из 3 похожих»…), или причина пропуска |
| `title_score`, `artist_score` | похожесть названия и исполнителя лучшего кандидата, 0–100 |
| `duration_delta` | насколько кандидат длиннее (+) или короче (−) трека из VK, сек |
| `version_conflict` | да — у кандидата другая версия песни |
| `margin` | отрыв от следующей другой записи, которую тоже можно было бы выбрать |

| Статус | Значение |
|---|---|
| добавлен | лежит в плейлисте |
| автоматически выбран | найден автоматически, но в плейлист ещё не добавлен (`--dry-run` или вы не подтвердили создание) |
| выбран вручную | вы выбрали кандидата в `--interactive` |
| пропущен: низкая уверенность | похожий трек нашёлся, но автоматически брать его рискованно (другая версия, другая длительность, несколько равных вариантов) |
| не найден | ничего похожего не нашлось |
| пропущен | вы нажали Enter в `--interactive` |
| битое название | вместо названия битрейт: трек не искался, исправьте строку в `tracks.txt` |
| дубликат | этот трек уже есть в плейлисте выше по списку |

## Как считается уверенность

Обе строки сначала нормализуются: регистр, ё→е, диакритика («Tiësto» = «Tiesto»), типографские тире, лишние пробелы и знаки, «ImagineDragons» = «Imagine Dragons», кириллица сравнивается ещё и в транслите с учётом разных систем латиницы («Ёлка» = «Yolka» = «Elka», «Максим» = «Maxim»). Из названия убирается шум вроде «(Official Audio)», «[Lyrics]», «(Visualizer)», «(Topic)», «(Remastered 2011)», «prod. by …» и технические хвосты VK. Исполнители разбиваются по «,», «&», «+», «x», «and», «feat.», «ft.», порядок не важен: «Bladee, Ecco2k» = «Ecco2k & Bladee».

Для каждого кандидата считаются отдельные признаки:

| Признак | Что это |
|---|---|
| `artist` | похожесть исполнителя 0–100; отдельно отмечается, совпал ли набор исполнителей целиком |
| `title` | похожесть названия 0–100: нечёткое сравнение строк, редакционное расстояние и — если все слова кандидата есть в названии из VK — сравнение наборов слов |
| containment | доля слов кандидата, которые есть в названии из VK («Girls Just Want to Have Fun» целиком входит в «Gotham CityGirls Just Want to Have Fun») |
| `duration` | разница длительности, если она известна с обеих сторон |
| version conflict | у кандидата другая версия: remix, live, acoustic, slowed, sped up, nightcore, instrumental, cover, demo, extended и т. п., ремикс другого автора, непонятная пометка вроде «[Phonk Edition]» |
| другая часть | в различающихся словах есть номер или «Pt. II», «Interlude», «Reprise», «Intro»…: «Song» и «Song 2», «ASPHALT 8» и «ASPHALT 9» — разные треки |
| лишние исполнители | лишний feat.-гость (−8), лишний основной исполнитель, как в мэшапах «FACE & Молчат Дома» (−10) |
| `score` | общая оценка: исполнитель 45%, название 55%, минус штрафы, плюс/минус длительность |

Длительность сильно влияет на уверенность: 0–2 с — очень сильный плюс, 3–5 с — сильный, 6–10 с — умеренный, 11–20 с — небольшой штраф, больше 20 с — сильный штраф (и автоматический выбор запрещён).

### Как принимается решение

1. **Отсев.** Кандидат не выбирается никогда, если у него другая версия, другая часть трека, чужой исполнитель (похожесть ниже 70) или длительность отличается больше чем на 20 с.
2. **Лучший из оставшихся.** Сравниваются все кандидаты из всех запросов. Если несколько почти равны (±3), побеждает ближайший по длительности (0–2, 3–5, 6–10, 11–20 с), затем с правильной пометкой версии, с точным набором исполнителей, с меньшим числом лишних слов, официальная и более популярная загрузка.
3. **Принятие** по любому из правил:
   - общий score ≥ 85;
   - **A:** исполнитель ≥ 92, длительность ±5 с, название ≥ 75 (≥ 70 при точном наборе исполнителей или длительности ±2 с);
   - **B:** исполнитель ≥ 85, длительность ±8 с, название ≥ 80;
   - **C:** название ≥ 92, исполнитель ≥ 75, длительность ±10 с;
   - **D:** исполнитель ≥ 95, длительность ±2 с, не меньше 65% слов кандидата есть в названии из VK;
   - без длительности, score 70–84 — только при исполнителе ≥ 85 и явно совпадающем названии.
4. **Соперники.** Правила A–D и средняя зона срабатывают, только если лучший кандидат явно лучше остальных: отрыв ≥ 10 баллов или соперник заметно хуже по длительности (на 5+ с), исполнителю, названию или версии. Если рядом другая версия песни, а различить их нечем, трек пропускается.

То есть совпавшие исполнитель и длительность позволяют названию отличаться сильнее, но никогда не отменяют проверку версии: к «Girls Just Want to Have Fun» не подставится «(instrumental remake)» той же длины. Выбор детерминирован: одни и те же кандидаты всегда дают один и тот же трек.

### Версия алгоритма и `--rematch`

В каждой записи `state.json` хранится поле `algo` — версия алгоритма сопоставления (сейчас 3) и `metrics` — признаки лучшего кандидата. Когда алгоритм меняется:

- ненайденные и пропущенные из-за низкой уверенности треки при следующем запуске перепроверяются сами: сначала по сохранённым кандидатам, потом только теми запросами, которых ещё не было;
- уже найденные автоматически треки не трогаются. Чтобы пересчитать и их, запустите с `--rematch`;
- ваш ручной выбор не пересчитывается никогда.

Старый `state.json` читается как есть, удалять его и заново выгружать `tracks.txt` не нужно. Чтобы пересчитать всё автоматическое новым алгоритмом и посмотреть подробности, ничего не меняя в SoundCloud:

```bash
python -m vk2sc --rematch --dry-run -v
```

Кандидаты берутся из `state.json`; к SoundCloud программа обращается, только если сохранённых кандидатов не хватило, и только с теми запросами, которых ещё не было. Если после пересчёта трек перестал считаться совпадением, при следующем обычном запуске он уйдёт из плейлиста.

## Частые ситуации

**«SoundCloud не отвечает или ограничил запросы».** На каждый запрос программа делает до 3 попыток с растущей паузой (при 429 — 10 и 20 с) и после третьей неудачи останавливается. Прогресс сохранён. Подождите 15–30 минут и запустите снова. Если это повторяется, увеличьте паузу: `--delay 3`.

**«Не удалось найти client_id на soundcloud.com».** SoundCloud поменял сайт, и способ получения client_id нужно обновлять. Все найденные треки сохранены.

**Плейлист удалили на сайте.** При следующем обновлении программа заметит это и предложит создать его заново (с `--yes` — создаст сама).

**Скрипт прервался между созданием плейлиста и записью в `state.json`.** При следующем запуске программа найдёт в аккаунте плейлист с тем же названием, созданный в прошлый раз, и продолжит в него, не создавая второй.

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Тесты `vk_export.js` запускают скрипт в headless Chromium на разных вариантах вёрстки VK: новой VK Музыки с бейджами битрейта от расширения (и такой же без названий, где должна быть ошибка), старой `audio_row`, только `data-audio`, гипотетической с виртуальным списком, неизвестной (эвристика) и пустой странице. Для них нужны Node.js и `playwright` (`npm i -g playwright && npx playwright install chromium`). Без этих инструментов тесты пропускаются.
